# What lives where (and what must never be committed)

**Rule:** secret *values* are never printed to chat, never written into repo files, never put into URLs or tool arguments that get logged.
Scripts read them from disk/secret store and pass them via environment or files with mode 600.

| Item | Where it lives | In git? | Backup |
|---|---|---|---|
| Android **upload keystore** `upload-keystore.jks` + `upload-keystore.properties` | `~/.config/<APP_SLUG>/` (chmod 700/600) | **NO** | **YES** — password manager / encrypted drive; loss = Google support ticket |
| Play App Signing key | Google holds it | — | Google; only the *fingerprint* goes to `assetlinks.json` |
| Debug keystore | auto-generated per machine (`~/.config/.android/` or `~/.android/`) | NO | not needed; its *fingerprint* goes to `assetlinks.json` |
| `google-services.json` (Firebase Android) | generated by `bin/google-services` from the secret store | **NO** (gitignored) | secret store is the source |
| `GoogleService-Info.plist` (Firebase iOS) | same idea | NO | secret store |
| APNs auth key / Sign in with Apple key `*.p8` | owner's Apple account download (**once**), then backend secret store | **NO** | secret store + owner |
| Provisioning profiles / certificates (`*.mobileprovision`, `*.p12`) | Xcode automatic signing manages them in the Mac keychain | NO | — |
| `mobile/ios/local.env` (TEAM_ID, DEVICE) | per machine | NO (gitignored) — Team ID itself is not secret | — |
| `mobile/android/local.properties` (sdk.dir) | per machine | NO | — |
| App Store Connect API keys (if CI) | CI secret store | NO | — |
| `MOBILE.md` answers, `assetlinks.json`, AASA, entitlements, PrivacyInfo | repo | **YES** (no secrets inside; fingerprints and Team ID are public identifiers) | git |

## Agent obligations
1. At Phase 2, **check `.gitignore`**: compare against `templates/gitignore.snippet`; append missing lines to the root `.gitignore`; show the diff.
2. Before every commit touching `mobile/`: `git status --short` and `git diff --cached --name-only` — block anything matching
   `*.jks *.keystore *.p8 *.p12 *.mobileprovision local.env local.properties google-services.json GoogleService-Info.plist upload-keystore.properties`.
   If the repo uses gitleaks/lefthook, let it run; never bypass hooks.
3. If a secret was committed by accident: stop, tell the user, do not rewrite history yourself; rotate the credential (new upload key via Play support, new `.p8`, new Firebase key) and let the user decide about history.
4. Never `cat`/`echo` a properties file or key; use `keytool -list`, `jq` on non-secret fields, or the `bin/fingerprint` helper. Never paste passwords into commands visible in logs (use `-storepass:env`).
5. Secret store (decided in Phase 0): SOPS+age (`sops -d --extract`), 1Password (`op read op://…`), plain files outside the repo, or a custom command —
   implemented in `android/bin/google-services`. Reuse the repo's own secret tooling (e.g. a `bin/secrets` wrapper) instead of inventing a new one.
6. Production secrets for the backend (Apple `.p8`, Firebase admin key) are added only through the repo's documented secret workflow, and only after they exist (many deploy tools fail on a missing referenced secret).
